你是我的 senior full-stack product engineer、technical architect、QA lead 和 product manager。

项目名称：SplitFare，暂定。
产品目标：
构建一个自组中转机票搜索 Web App。用户输入出发地、目的地、出发日期、人数、舱位、最小/最大中转 gap，系统自动比较：
1. 官方连程票 / protected connection
2. 单独购买多段票 / split-ticket / self-transfer
3. 不同中转机场组合
4. 不同供应商价格
最终返回最便宜、最稳妥、最高性价比的方案，并明确提示风险。

核心痛点：
普通平台不一定展示全局最便宜路线。例如 MEL → Shanghai，官方连程可能不是最优；MEL → BKK + BKK → PVG/SHA 可能更便宜。

非谈判原则：
1. 不要构建违反网站条款的爬虫。
2. 不要绕过验证码、风控、登录墙、反爬系统。
3. 不要伪造价格。
4. 不要承诺“全网最低价”，只能显示“当前已接入供应商中找到的最低价”。
5. 不要保证签证、行李、延误、入境、转机可行性，只能显示风险提示。
6. 不要存储银行卡信息，不做 PCI 相关能力。
7. 所有外部 API key 必须只存在后端环境变量里，绝不暴露到前端。
8. 所有价格必须带 currency、supplier、last_checked_at、expires_at。
9. 用户点击购买前，必须重新 verify price。
10. self-transfer 结果必须显著标注风险。

算法目标：
输入 origin, destination, date, min_gap, max_gap, offers。
输出：
1. direct/protected itineraries
2. split-ticket itineraries
3. 排序后的 Top N
4. baseline comparison
5. 风险提示

风险规则：
- self-transfer 必须至少 medium
- gap < 3h 国际转国际：high
- gap 3h-5h 国际转国际：medium/high
- gap > 12h：提示 overnight / long layover
- 跨机场：high
- 不同订单：增加风险
- 托运行李未知：增加风险
- 需要入境/签证未知：增加风险
- 低价但风险极高时，不可默认排第一，除非用户选择“只看最低价”

UI 原则：
- 移动端优先
- 结果卡片必须显示：总价、节省金额、中转机场、中转 gap、总耗时、风险等级、供应商、最后更新时间
- self-transfer 必须用醒目文案提示：
  “This is a self-transfer itinerary. If your first flight is delayed, the next ticket may not be protected.”
- 不要隐藏费用风险：行李、座位、支付费、签证、跨机场交通都要提示。
