# SplitFare Release Checklist — Phase 17–19

## Product alignment

- [x] Active UI discovers candidate routes without live fare data.
- [x] No paid flight API or OTA scraping is used by route discovery.
- [x] No flight numbers, exact schedule, confirmed price or guaranteed saving is generated.
- [x] Every route is visibly marked candidate/self-transfer.
- [x] First and second legs have backend-generated provider search entries.
- [x] Provider links are redirect-only and never enter ranking.
- [x] Legacy Mock price search is not used by the production UI.

## Route quality and risk

- [x] Hub configuration is backend-owned and selected by route region.
- [x] Airport coordinates have one authoritative source.
- [x] Great-circle direct/split distance and detour ratio are tested.
- [x] Extreme detour policy is explicit.
- [x] Stable airport-level signatures deduplicate routes.
- [x] Same-city alternative airports remain distinct.
- [x] Cross-airport routes remain distinct and receive extreme structural risk.
- [x] Structural, schedule-dependent and unknown risk are separated.
- [x] Best route, lowest risk, shortest detour and simplest transfer sorting are tested.

## Provider links

- [x] Provider configuration is not stored in React.
- [x] URLs are generated by the backend and require HTTPS.
- [x] Unsafe protocols and example hosts are rejected.
- [x] Unsupported prefill uses provider homepage/manual-search semantics.
- [x] No private provider-page activity is tracked.
- [x] Platform reminder states that price and schedule are controlled by the provider.

## Manual comparison

- [x] Two segment prices and six fee categories use integer minor units.
- [x] Protected-ticket price is optional; no baseline means no saving.
- [x] Mixed currencies, negatives, excessive amounts and invalid precision are rejected.
- [x] Neutral decision rules are centralized outside React.
- [x] Values are explicitly identified as user-entered, not supplier-confirmed.
- [x] localStorage uses `splitfare:manual-comparisons:v1`.
- [x] Save, modify, reset, clear-all, migration, corruption recovery and JSON export are implemented.
- [x] Language switching and refresh preserve records.

## Internationalization and mobile

- [x] Route, risk, provider and manual-comparison UI has English and Chinese copy.
- [x] Language switching does not repeat route discovery.
- [x] 375px Playwright covers both leg buttons and manual amount inputs.
- [x] Original continent/country/city selector remains in the E2E path.
